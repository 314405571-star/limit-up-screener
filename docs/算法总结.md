# 首板 / 炸板池与三套过滤器：算法总结

> 对应代码：`src/limitboard/`（核心为纯标准库，无 pandas / numpy / 网络）。
> 对应原始实现：`legacy/` 下 V1、V2、V3 三个版本，逐字保留。

---

## 0. 一句话

每天收盘后，把全市场涨停的股票分成**首板池**（今天第一次封板）和**炸板池**
（今天摸到过涨停但收盘没封住），再用三套过滤器各挑一遍，最后让候选过一道**量压测试**。

它是一个**收盘后的观察名单生成器**，不是交易系统——这一点后面会反复强调。

---

## 1. 策略骨架

```
全市场 A 股
   │  一次日线取数（150 根）
   ▼
计算涨停价（分板块、分 ST、分上市天数）
   │
   ├─ 今日收盘 = 涨停价          → 封板
   ├─ 今日最高 ≥ 涨停价且未封    → 炸板
   └─ 其余                      → 无关
   │
   ▼
结合昨日的封板状态分池
   ├─ 昨日封板                    → 连板（不在本策略范围）
   ├─ 昨日未封 + 今日封板         → 首板池
   ├─ 昨日未封 + 今日炸板         → 炸板池
   └─ 昨日无数据                  → unknown_prev（不猜）
   │
   ▼
首板池：策略一（低开） ├ 策略二（高开）
炸板池：策略三（弱转强）
   │
   ▼
策略二、策略三再过一遍压力测试
   │
   ▼
最终名单（观察，不是买入指令）
```

## 2. 涨停价：这条规则只有十个字，但很容易写错

| 板块 | 代码 | 正常 | ST | 上市初期 |
|---|---|---:|---:|---|
| 主板 | 60x / 00x | 10% | 5% | 首日 44%（按无涨跌幅处理） |
| 创业板 | 300x | 20% | **20%** | 前 5 个交易日无限制 |
| 科创板 | 688x | 20% | **20%** | 前 5 个交易日无限制 |
| 北交所 | 8xxxxx / 4xxxxx | 30% | 30% | 首日无限制 |

### 2.1 取整必须"四舍五入到分"

```
涨停价 = round_half_up(前收盘价 × (1 + 幅度), 0.01)
```

交易所是**四舍五入**。Python 的 `round()` 是**银行家舍入**（half-to-even），
而且先转成二进制浮点再舍入。两者在 `.xx5` 边界上会差一分钱：

```
5.35 × 1.1 = 5.885
  交易所   → 5.89
  内置 round → 5.88
```

一分钱意味着什么？收盘 5.88 的股票**没有封板**，但按 5.88 的"涨停价"判断，
它"封住了"。在 5–50 元的区间里，**约 1.2% 的前收盘价会落进这个陷阱**
（4500 个价格里有 56 个）。

本项目用 `Decimal` + `ROUND_HALF_UP`：

```python
ratio = Decimal(str(limit_ratio(code, is_st)))
price = (Decimal(str(preclose)) * (1 + ratio)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
```

### 2.2 ST 的幅度取决于板块，不是"一律 5%"

2020 年注册制改革后，创业板和科创板的 ST 股票仍然是 **20%** 涨跌幅；
北交所是 30%。只有主板 ST 才是 5%。

原实现写成：

```python
if is_st:
    ratio = 0.05
```

于是**创业板 ST 股票当天涨 10%、根本没有封板，也会被算成"涨停"**，直接进首板池。

### 2.3 上市初期的"涨停"是伪命题

创业板 / 科创板上市前 5 个交易日不设涨跌幅限制。一只上市第 3 天涨 40% 的股票，
按 20% 规则算出来的"涨停价"毫无意义，但在原实现里会被判成封板，进入首板池。

本项目引入 `has_price_limit(code, listed_bars)`：上市不足 5 个交易日（创业板/科创板）
或不足 1 个交易日（主板）时，当天不参与涨停判定，记作 `no_limit`。

## 3. 两个池子

### 3.1 判定只看日线

```
封板 = 收盘价 ≥ 涨停价
炸板 = 最高价 ≥ 涨停价 且 收盘价 < 涨停价
```

原实现为了判断"盘中是否摸过涨停"，对**每一只股票**都额外请求一次 5 分钟线
（全市场 5000 只 = 5000 次多余请求）。但 `最高价 ≥ 涨停价` 就是"摸过涨停"的定义，
日线里已经有了。**这一整轮请求可以直接删掉。**

### 3.2 "昨天"不等于"日历上的昨天"

原实现这样找前一日：

```python
dt = target_date - 1 天
while dt 是周末: dt -= 1 天          # 只跳周末
```

国庆、春节后的第一个交易日，这个日期是**休市日**。查询返回空，
`prev_limit_up` 就是 `False`，于是**所有连板股都会被当成首板**。
停牌一天再复牌的股票也一样。

本项目的做法：**前一日 = 该股票上一根有交易的 K 线**（`history[-2]`），
不依赖日历。一根连续的历史序列，天然跳过了节假日和停牌。

如果前一根 K 线确实不存在（例如把单日快照喂进来），则标记为 `unknown_prev`
并**排除出池**，而不是默认"昨天没涨停"。把未知当成否，是这类脚本最常见的错误来源。

### 3.3 连板

昨日封板的股票记作 `continued`，不进首板池，也不进炸板池——这是"首板策略"的定义决定的。
原实现没有这个桶，连板股会被丢进 `none`，从结果上看没问题，但审计时看不出它去哪了。

## 4. 三套过滤器

### 4.1 策略一：首板低开

| 条件 | 判据 |
|---|---|
| 相对位置 | 收盘价在过去 **60 个交易日**（不含今天）的高低区间中的位置 ≤ 0.50 |
| 成交额 | 当日成交额 ≥ 1 亿元 |

```
rp = (H - close) / (H - L)      # 0 = 贴近区间高点，1 = 贴近低点
```

注意 `rp` 的语义：**数值越小越靠近近期高点**。`rp ≤ 0.5` 表示收盘价位于
过去 60 日区间的上半部分——策略名里的"低开"指的是次日开盘，不是这个指标。

原实现把**今天这根涨停 K 线**也算进 60 日区间。封死的票今天的最高价就等于收盘价，
所以只要今天的收盘创了 60 日新高（突破型首板最常见的一种），`H` 就被今天自己顶到
`close`，`rp` 恰好是 0——**区间被这次涨停本身撑开了**，指标失去意义。
把今天排除后，这个数字才回到"今天之前这只股票站在哪"的本意。

### 4.2 策略二：首板高开

| 条件 | 判据 |
|---|---|
| 收盘溢价 | `(收盘价 / 当日均价 - 1) × 100 ≥ 7` |
| 成交额 | 5.5 亿 ≤ 成交额 ≤ 20 亿 |
| 市值 | 70 亿 ≤ 流通市值 ≤ 520 亿 |

当日均价用 `成交额 / 成交量` 近似（baostock 的 `amount` 单位为元、`volume` 为股）。

**命名问题**：原实现把 `(close - vwap) / vwap` 叫作"获利比例"，字面意思是
"多少比例的持仓者处于盈利状态"。它实际是**收盘价相对当日成交均价的溢价**。
两者完全不同：前者需要筹码分布，后者只需要一根 K 线。本项目改名为 `vwap_premium`。

### 4.3 策略三：弱转强

针对炸板池：

| 条件 | 判据 |
|---|---|
| 三日涨幅 | `close[-1] / close[-4] - 1 ≤ 28%` |
| K 线实体 | `(close / open - 1) × 100 ≥ -5` |
| 收盘溢价 | `vwap_premium ≥ -4` |
| 成交额 | 3 亿 ≤ 成交额 ≤ 19 亿 |
| 市值 | 70 亿 ≤ 流通市值 ≤ 520 亿 |

原实现用 `close[-1] / close[-3]`，那是**两个交易日**的涨幅，却标成"近 3 日"。
要覆盖 3 个交易日的涨跌，需要 4 个收盘价。

### 4.4 市值区间：上下界必须用同一个量

原实现：

```python
if total_cap < 70 or float_cap > 520:      # 总市值下限 + 流通市值上限
    continue
```

下限检查**总市值**，上限检查**流通市值**。一只总市值 600 亿、流通市值只有 50 亿
的次新股（大股东锁定、流通盘很小）会**通过**这个过滤——它既不在"70 亿以上流通盘"
的意图里，也不在"总市值不超过 520 亿"的意图里。

本项目把上下界统一施加在**流通市值**上（`Config.cap_basis="float"`），
也可以配置成总市值。关键是**一个量**。

## 5. 压力测试

```
阻力位 = 昨日最高价
在昨日之前找最近一次"收盘价 > 阻力位"的交易日
取该日之后 5 个交易日的最大成交量 V
要求：今日成交量 ≥ 0.9 × V
```

几何含义：上一次股价冲过这个位置时，有 V 手筹码在那里换手；
这些筹码构成"上方套牢盘"。今天要再冲一次，成交量必须接近当时，
否则说明承接不足。

### 5.1 两个被写反的分支

```python
if idx is None:
    continue          # ← 没有任何一天收盘价高于阻力位
```

`idx is None` 的意思是：**这只股票处在历史新高，上方根本没有套牢盘**。
这是打板里最干净的一类图形，而代码把它 `continue` 掉了。
本项目把它放行，并记 `pressure_note="new_high"`。

第二种：突破发生在昨天，观测窗口是空的（`obs_df.empty`）。原实现同样拒绝。
本项目放行，记 `fresh_breakout`——窗口里没有数据，说明"无法测量"，
而不是"测量结果不合格"。这两种情况必须分开。

### 5.2 一个文档与实现的偏差

注释写"找**首个**收盘价 > T-1 高点的位置"，代码是从后往前找，得到的是**最近一次**
突破。按交易含义，最近一次才是应该看的（更早的套牢盘可能已经消化）；
本项目保留"最近一次"的语义，并把注释改成事实。

## 6. 漏斗与输出

```
18 只 → 1 只无涨跌幅限制 → 3 只非涨停 → 2 只连板
      → 9 只首板 + 3 只炸板
      → 策略一 7 只，策略二 4 只（过压力 3 只），策略三 1 只（过压力 1 只）
      → 最终 8 只
```

输出文件（都带交易日）：

| 文件 | 内容 |
|---|---|
| `output/首板池_<日期>_<时间戳>.csv` | 今日首板 |
| `output/炸板池_<日期>_<时间戳>.csv` | 今日炸板 |
| `output/全部候选_<日期>_<时间戳>.csv` | 每只股票的状态与**每个过滤器失败的原因** |
| `output/最终选股_<日期>_<时间戳>.csv` | 最终名单 |

`检查明细` 一列形如：

```
low_open:relative_position | high_open:amount,vwap_premium
```

原实现只打印"策略一（首板低开）: 5 只"，哪只、为什么被刷，全都丢了。

## 7. 缺陷清单

| # | 缺陷 | 后果 | 修复 | 测试 |
|---|---|---|---|---|
| 1 | `round(preclose*(1+r), 2)` | 1.2% 的价格算出的涨停价低一分，未封板的票被算成封板 | `Decimal` + `ROUND_HALF_UP` | `test_limit_price_uses_exchange_rounding` |
| 2 | ST 一律 5% | 创业板 ST 涨 10% 被当成涨停 | 幅度按板块 × ST 二维查表 | `test_st_keeps_its_board_limit` |
| 3 | 无视上市初期无涨跌幅 | 次新股 +40% 进首板池 | `has_price_limit` + `no_limit` 状态 | `test_no_limit_window_for_new_listings` |
| 4 | 前一交易日只跳周末 | 节后第一天全部连板被当成首板 | 用 `history[-2]`；未知则 `unknown_prev` | `test_missing_previous_bar_is_not_a_first_board` |
| 5 | 相对位置窗口含今天 | 一字板 `rp ≡ 0`，条件恒真 | 排除今天 | `test_relative_position_uses_the_prior_range` |
| 6 | 压力测试 `idx is None → continue` | 创新高的最强票被刷掉 | 放行并标记 `new_high` | `test_pressure_passes_a_new_high` |
| 7 | 市值下限用总市值、上限用流通市值 | 小流通盘次新股通过 | 上下界统一口径 | `test_market_cap_band_uses_one_measure` |
| 8 | "近 3 日涨幅"用 3 个收盘价 | 实际是 2 日 | 4 个收盘价 | `test_three_day_return_uses_four_closes` |
| 9 | 5 分钟线只用来取 `max(high)` | 每只股票多一次请求 | 用日线最高价 | `test_daily_high_is_enough_to_see_a_touch` |
| 10 | 每只股票 4–6 次查询 | 5000 只 ≈ 2.5 万次请求 | 一次 150 根日线，落盘缓存 | `test_pipeline_end_to_end` |

另外：输出文件名带时间戳却不带交易日；`list(set(final_codes))` 让最终名单每次顺序不同；
"获利比例"其实是 VWAP 溢价；`get_share_capital` 用的是上一季度股本（市值会滞后）。

## 9. 局限（比参数更重要）

1. **没有回测，也没有交易模型。** 代码在 T 日收盘后给出名单，**不包含任何买点、
   卖点、仓位**。它不知道你 T+1 是集合竞价买、开盘买、还是盘中买。
2. **"封板"不等于"买得到"。** 一字板全天无卖盘，名单里的股票可能根本买不进。
   本项目甚至能明确标出这类票（`vwap_premium = 0`），但**买不买得到是另一回事**。
3. **成交额与市值来自季报。** `query_profit_data` 的股本是上一季度数据，
   送转、增发之后市值会失真。
4. **涨停价在除权日会错。** 本策略用不复权价格（这是对的），但除权日的
   `preclose` 需要是除权后的价格，数据源是否一致要自行核对。
5. **没有退市/ST 摘帽的处理。** `isST` 按当日数据取，ST 股票的风险更高，
   而策略不会因此额外收紧。
6. **幸存者偏差。** 股票池是"当前上市"的代码，退市股不在样本里。
7. **样本极小。** 每天 10–20 只首板，任何统计结论都需要几百个交易日的积累。

一句话：**这是一份观察名单的生成器，不是收益来源。** 仓库里没有任何收益曲线，
也不声称有超额收益。
