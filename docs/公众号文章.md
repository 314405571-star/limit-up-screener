# 最强的首板，死在了最后一道过滤器

> 一份流传很广的打板脚本，每天能刷出十几只"首板"。我把它拆开跑了一遍，
> 发现池子里混着连板，创新高的票被当成"有压力"刷掉，创业板 ST 涨 10% 被算成涨停。
> 三个错误，都不会报错。

---

## 一、先说结论

打板这件事，第一步不是买，是**分类**：

- **首板**：昨天没涨停，今天涨停。这是策略关心的对象。
- **炸板**：今天盘中摸到过涨停，收盘没封住。第二天可能"弱转强"。
- **连板**：昨天已经涨停。不在首板策略的范围里。

分错了，后面所有过滤都是在错的池子里挑。

我复刻的那份脚本，分类这一步有**三个静默错误**。它们不会抛异常，
只会在某些天让池子悄悄变脏。下面逐条拆。

---

## 二、先看它本来长什么样

收盘后跑一遍：

```
全市场 A 股
  → 算涨停价（主板 10%、创业板/科创板 20%、ST 5%、北交所 30%）
  → 封板 / 炸板
  → 结合昨天的状态分成 首板池 与 炸板池
  → 首板池：策略一（低开）+ 策略二（高开）
  → 炸板池：策略三（弱转强）
  → 策略二、三再过一遍"压力测试"
  → 观察名单
```

三套过滤器的条件也很具体：

| 策略 | 条件 |
|---|---|
| 首板低开 | 收盘价在过去 60 日区间的上半部；成交额 ≥ 1 亿 |
| 首板高开 | 收盘价高于当日均价 7%；成交额 5.5–20 亿；流通市值 70–520 亿 |
| 弱转强 | 三日涨幅 ≤ 28%；K 线实体 ≥ -5%；VWAP 溢价 ≥ -4%；成交额 3–19 亿 |

压力测试是这套系统里最有意思的一步：**上一次股价冲过昨天最高价时，
那 5 天里最大的一笔成交量是多少？今天的量必须达到它的 90%。**
不够，说明承接不足，上方套牢盘还没消化。

思路都对。实现里有坑。

## 三、Bug 1：节后第一天，整个池子都是连板

脚本这样找"前一个交易日"：

```python
dt = target_date - 1 天
while dt 是周末:
    dt -= 1 天
```

只跳周末。

国庆假期后的第一个交易日是 10 月 8 日，这个函数返回 **10 月 7 日**——休市日。
查询返回空，于是：

```python
prev_limit_up = check_is_limit_up(prev_daily, code) if prev_daily else False
```

`False`。

**昨天有没有涨停？不知道。但代码默认是"没有"。** 于是所有连板股都被当成首板，
涌进池子。停牌一天再复牌的股票，也一样。

修法不是补一个节假日表，而是换数据源：**前一日 = 这只股票上一根有交易的 K 线**。
一根连续的日线序列，天然跳过了周末、节假日和停牌。

```python
prev_sealed = classify_day(history[-2], ...) == "sealed"
```

如果前一根 K 线确实不存在，就标 `unknown_prev` 并**排除**——
"不知道"和"没有"是两件事。

## 四、Bug 2：最强的票，被最后一道过滤器杀了

这是标题里的那个。

压力测试的代码长这样：

```python
idx = None
for i in range(len(df_before) - 1, -1, -1):
    if df_before.iloc[i]['close'] > pressure_high:
        idx = i
        break
if idx is None:
    continue          # ← 这里
```

`idx is None` 意味着什么？

意味着**在昨天之前，没有任何一天的收盘价高于昨天的最高价**。
翻译成人话：这只股票正在**创历史新高**，上方根本没有套牢盘。

这是打板里图形最干净的一类——没有解套盘，没有前期高点压制。
而脚本给它 `continue` 掉了，理由是"找不到参照量"。

一个"压力测试"，把**没有压力**的股票判成了失败。

修复：没有参照就放行，并记下原因。

```python
if index is None:
    return Check(True, (), {"pressure_note": "new_high"})
```

同样的问题还有第二种情况：突破发生在昨天，观测窗口是空的。
脚本也 `continue`。空窗口的正确含义是"无法测量"，不是"不合格"。
现在它记作 `fresh_breakout` 并放行。

**这两个分支加起来，把最该买的票全部排除了。** 而输出里只有一句
"策略二通过压力测试: 3 只"，你根本看不出少了谁。

## 五、Bug 3：创业板 ST 涨 10%，不是涨停

涨停价的计算是这样的：

```python
if is_st:
    ratio = 0.05
else:
    ratio = 0.20 if code.startswith(('30', '68')) else 0.10
```

ST 一律 5%。

但 2020 年注册制改革之后，**创业板和科创板的 ST 股票仍然是 20%**，
北交所是 30%。只有主板 ST 才是 5%。

后果很直接：一只创业板 ST 股票（300 开头）当天涨 10%，
按 5% 的规则，`收盘价 ≥ 前收 × 1.05` 成立——**它被判定为封板，进了首板池**。
而它离真正的涨停（+20%）还差十个点。

修复是一张二维表：

```python
{"main": 0.05, "growth": 0.20, "bj": 0.30}[board]
```

顺手还有第三个：**上市初期本来就没有涨跌幅限制**。
创业板、科创板前 5 个交易日不设涨跌幅，一只次新股 +40% 是完全正常的，
而脚本会按 20% 算出一个"涨停价"，然后宣布它封板了。

## 六、还有几个便宜的

**1. 涨停价差一分钱。**

交易所是四舍五入到分，Python 的 `round()` 是银行家舍入 + 二进制浮点。

```
5.35 × 1.1 = 5.885
  交易所   → 5.89
  内置 round → 5.88
```

收盘 5.88 的股票**没有封板**，但按 5.88 的"涨停价"判断，它封住了。
在 5–50 元区间里，约 **1.2%** 的前收盘价会落进这个陷阱。

**2. "近 3 日涨幅"其实是 2 日。**

```python
cum_pct = (last_close - first_close) / first_close * 100   # 用了最后 3 个收盘价
```

3 个收盘价之间只有**两个**涨跌幅。要覆盖 3 个交易日，需要 4 个价格。

**3. 市值的下限和上限，量的不是同一个东西。**

```python
if total_cap < 70 or float_cap > 520:
```

下限查**总市值**，上限查**流通市值**。一只总市值 600 亿、流通市值 50 亿的次新股
会顺利通过——它既不在"流通市值 70 亿以上"的意图里，也不在"总市值 520 亿以内"的意图里。

**4. 60 日相对位置，把今天算了进去。**

封死的票，今天的最高价 = 收盘价。只要它创了 60 日新高，
区间的上沿就被今天自己顶到了收盘价，`rp` 恰好等于 0——指标废了。
应该用**今天之前**的 60 根 K 线。

**5. 每只股票请求 4–6 次。**

今天的日线、昨天的日线（按日期查）、5 分钟线、策略里再查一次今天的日线……
全市场 5000 只，两万多次网络往返。

而那条 5 分钟线，只为了取一个 `max(high)`。**日线的最高价里已经有了。**
一次请求就够。

## 七、修完之后，跑一遍

仓库里有一个完全离线的 demo：18 只合成股票，固定随机种子，不联网。

```
全部 18 只
  → 1 只处于无涨跌幅窗口（次新）
  → 3 只非涨停
  → 2 只连板
  → 9 只首板 + 3 只炸板
  → 策略一 7 只、策略二 4 只（过压力 3 只）、策略三 1 只（过压力 1 只）
  → 最终 8 只
```

把同一份数据交给原脚本，**18 只里有 4 只的归类不同**：

| 代码 | 情形 | 原脚本 | 本项目 |
|---|---|---|---|
| sz.300007 | 创业板 ST，+10% | 首板 | 无关 |
| sh.688008 | 科创板次新，+40% | 首板 | 无涨跌幅 |
| sh.600010 | 节后首日，昨日封板 | 首板 | 连板 |
| sh.600012 | 前收 5.35，收 5.88 | 首板 | 无关（真涨停价 5.89） |

每一条都对应上面一个 bug。这不是理论推演，是可复现的输出。

## 八、为什么值得一个 star

因为**这些 bug 不会报错**。

它们不会让程序崩溃，只会在某一天让首板池里混进连板，或者在另一天把最强的票
悄悄刷掉。第二天你看名单，完全不知道少了什么。

所以这个仓库把它做成了可以测试的形状：

- **核心是纯标准库**，`src/limitboard/` 不 import pandas、numpy、网络。
  一只股票的一天，可以用二十根手写的 K 线复现。
- **20 个测试，每个 bug 一个名字**：
  `test_pressure_passes_a_new_high`、`test_st_keeps_its_board_limit`、
  `test_limit_price_uses_exchange_rounding`……
  测试名就是墓碑。
- **失败原因被写下来**：每只股票有 `state`（封板/炸板/无限制/连板/未知），
  每个过滤器有 `reasons`，CSV 里能查到它死在哪一条。
- **一次取数**：全市场两万次请求变成每只一次 + 落盘缓存。
- **四张图**，都来自离线 demo，可以自己跑出来。

```bash
git clone https://github.com/314405571-star/limit-up-screener
cd limit-up-screener
python examples/demo_boards.py
python tests/test_strategies.py
```

## 九、三条必须说清楚的话

1. **这不是一个能赚钱的策略。** 仓库里没有回测，没有收益曲线，也没有"月翻倍"的截图。
   它是一份观察名单的生成器。

2. **"封板"不等于"买得到"。** 一字板全天没有卖盘，名单里的票可能根本买不进。
   demo 里就有一只一字板（`vwap_premium = 0`），策略二直接把它拒了——
   但即便如此，买不买得到是另一个问题。

3. **代码只负责 T 日收盘后的分类，不包含任何买卖点。**
   你 T+1 是集合竞价买、开盘买还是盘中买，仓位多少，止损放在哪，
   它一句话都没说。

那份脚本最有价值的地方，不是它每天刷出的名单，而是它逼着你把
"什么算涨停"这件事想清楚。**涨停价是 5.88 还是 5.89，
创业板 ST 是 5% 还是 20%，创新高算不算"有压力"**——
这些问题的答案，比任何参数都重要。
